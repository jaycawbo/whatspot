## Session Format Rules

### Starting Every Session
Begin with a plan stating:
- What we're tackling today (task list)
- Which files will be touched
- Expected outcome of each change

### Ending Every Session
Always produce two documents:
1. Full session log — every change made, what it does, 
   confirmed working or not, any regressions
2. Jake's summary — plain English, non-technical, 
   what was built and why, what's next

### After Every Lovable Prompt
Before moving on, confirm:
- Did Lovable actually implement the change (paste file to verify)
- Did any protected files get touched unexpectedly
- Does the behavior match the expected outcome

## Founder Learning Rules
After every prompt or technical decision, Claude provides
a plain-English explanation of what the code does and why.
Format: brief paragraph after the prompt, NOT inside the prompt.
Topics to cover: what the function/hook/pattern does,
why we chose this approach, what problem it solves.
Examples used wherever possible.
No jargon without explanation.
This section stays OUT of Lovable prompts entirely.
